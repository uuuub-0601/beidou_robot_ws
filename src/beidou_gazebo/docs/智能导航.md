# 老人北斗项目：智能导航启动与解读

本文档整理主目录中的 `# 智能导航.yaml`，并按当前 `beidou_robot_ws` 的模块职责说明启动顺序、话题链路和 RViz 配置。原始文本版本保存在同目录的 [`智能导航.yaml`](./智能导航.yaml) 中。

## 1. 系统链路

```text
Gazebo elderly_final 世界
        |
        +--> elderly_walker：老人连续移动
        |       |
        |       +--> elderly_pose_bridge / elderly_beidou
        |               |
        |               +--> /elderly_position (PoseStamped)
        |                         |
        |                         +--> geofence：SAFE/WARNING/DANGER
        |                         |       |
        |                         |       +--> /elderly_geofence_state
        |                         |       +--> voice_alert：中文语音报警
        |                         |       +--> elderly_rviz_status：RViz 状态文字
        |                         |
        |                         +--> companion_v2：动态跟随目标
        |                                 |
        |                                 +--> Nav2 跟随老人
        |
        +--> Nav2：地图、定位、规划和控制
```

主要数据接口如下：

| 话题 | 类型 | 用途 |
| --- | --- | --- |
| `/elderly_position` | `geometry_msgs/msg/PoseStamped` | 模拟北斗输出的老人地图坐标 |
| `/elderly_geofence_state` | `std_msgs/msg/String` | 电子围栏状态：`SAFE`、`WARNING`、`DANGER` |
| `/elderly_geofence_markers` | `visualization_msgs/msg/MarkerArray` | 原有电子围栏区域 |
| `/elderly_geofence_status_marker` | `visualization_msgs/msg/Marker` | RViz 中跟随老人位置的状态文字 |
| `/elderly_follow_target` | `geometry_msgs/msg/PoseStamped` | Companion v2 计算的跟随目标 |
| `/goal_update` | `geometry_msgs/msg/PoseStamped` | 给 Nav2 GoalUpdater 的动态目标更新 |

`elderly_rviz_status` 只做可视化：订阅老人位置和围栏状态，发布一个 `TEXT_VIEW_FACING` Marker；它不发布 `/cmd_vel`，也不发送 Nav2 Goal。

## 2. 推荐启动顺序

每个终端都先执行：

```bash
source /opt/ros/jazzy/setup.bash
source ~/beidou_robot_ws/install/setup.bash
```

然后按下面顺序启动。RViz 和状态文字节点可以在数据节点之后启动，RViz 本身也可以提前打开。

### 终端一：Gazebo 世界

```bash
ros2 launch beidou_gazebo elderly_final.launch.py
```

启动 `elderly_final` 世界、老人模型和机器人模型。

### 终端二：Nav2

```bash
ros2 launch beidou_gazebo nav2_final_navigation.launch.py
```

启动地图服务器、AMCL、规划器、控制器和生命周期管理器。不要重复启动第二个 Nav2 实例。

### 终端三：老人移动

```bash
ros2 launch beidou_gazebo elderly_walker.launch.py
```

让 Gazebo 中的老人连续移动。

### 终端四：模拟北斗

```bash
ros2 launch beidou_gazebo elderly_beidou.launch.py
```

通过 Gazebo 位姿桥接和 `beidou_position_publisher` 持续发布 `/elderly_position`。

### 终端五：电子围栏

```bash
ros2 launch beidou_gazebo geofence.launch.py
```

订阅 `/elderly_position`，发布电子围栏状态和原有围栏 Marker。状态变化典型顺序为：

```text
SAFE -> WARNING -> DANGER -> WARNING -> SAFE
```

### 终端六：老人跟随

```bash
ros2 launch beidou_gazebo companion_v2.launch.py
```

启动运动估计和 Companion v2。Companion 根据老人位置和运动趋势生成动态跟随目标，再交给 Nav2 执行。

### 终端七：中文语音报警

```bash
ros2 launch beidou_gazebo voice_alert.launch.py
```

订阅 `/elderly_geofence_state`。进入 `DANGER` 时播放 Piper 中文普通话报警；语音节点不改变老人位置、围栏判断或导航目标。

### 终端八：RViz 状态文字节点

```bash
ros2 launch beidou_gazebo elderly_rviz_status.launch.py
```

该节点发布 `/elderly_geofence_status_marker`。Marker 文字显示在老人位置上方约 `0.9 m`，状态文字大小默认为 `0.5 m`。

### 终端九：RViz

```bash
rviz2
```

## 3. RViz 配置

将 `Fixed Frame` 设置为：

```text
map
```

依次添加以下 Display：

| Display 类型 | Topic 或设置 |
| --- | --- |
| `Map` | Topic：`/map` |
| `RobotModel` | 使用默认机器人描述 |
| `MarkerArray` | Topic：`/elderly_geofence_markers` |
| `Pose` | Topic：`/elderly_position` |
| `Marker` | Topic：`/elderly_geofence_status_marker` |

最后一个 `Marker` Display 就是老人旁边的状态文字。它与原有的 `MarkerArray` 电子围栏显示相互独立。

## 4. 常用检查命令

确认老人位置在持续更新：

```bash
ros2 topic echo /elderly_position
```

确认电子围栏状态：

```bash
ros2 topic echo /elderly_geofence_state
```

确认 RViz 状态文字：

```bash
ros2 topic echo /elderly_geofence_status_marker
```

只看文字字段：

```bash
ros2 topic echo /elderly_geofence_status_marker --field text
```

检查节点和接口：

```bash
ros2 node info /elderly_rviz_status
ros2 topic info /elderly_follow_target
ros2 topic info /goal_update
```

## 5. 故障排查

- 没有 `/elderly_position`：先确认 Gazebo、Walker 和 `elderly_beidou.launch.py` 都已启动。
- 没有 `/elderly_geofence_state`：确认 `geofence.launch.py` 已启动，并检查电子围栏节点日志。
- RViz 没有状态文字：确认 `elderly_rviz_status.launch.py` 正在运行、Fixed Frame 是 `map`，且 Marker Topic 拼写为 `/elderly_geofence_status_marker`。
- Companion 没有跟随目标：确认 Nav2 已完全启动，再检查 `/elderly_position`、`/elderly_follow_target` 和 `/goal_update`。
- 没有 `/clock` 的单独测试环境：启动状态文字节点时可使用 `use_sim_time:=false`；完整 Gazebo 运行时保持默认仿真时间即可。

## 6. 停止系统

按 `Ctrl+C` 关闭各终端中的 launch。若 Nav2 报告单实例锁或共享内存残留，先确认旧的 Gazebo/Nav2 进程已经退出，再重新启动；这类提示通常是运行环境残留，不需要修改导航核心参数。
